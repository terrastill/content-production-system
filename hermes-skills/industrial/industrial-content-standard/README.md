# Industrial Content Standard Reference

This reference is intentionally included as a portable, non-secret quality baseline for the article-generation Skill. It is not a company knowledge base and contains no customer data or credentials.

## Core requirements

- Determine search intent, reader type, article type, content boundary, and commercial relevance before planning.
- Start with a direct answer; do not lead with generic market background or a brand name.
- Give every H2 a distinct task. Keep H3 items on the same classification dimension.
- Separate process, equipment, technical design features, and application conditions.
- Keep comparisons parallel; separate option explanation, comparison, and selection advice.
- Use lists and tables only when they improve retrieval of steps, equipment roles, comparisons, conditions, or cause/effect.
- Use four to six FAQ entries that add value beyond headings already answered in the body.
- Use one natural CTA linked to verified capabilities and request useful project information.
- Do not present generic knowledge as company facts. Preserve source, conditions, and uncertainty.
- Do not invent equipment models, operating data, yield, price, delivery, emissions conclusion, certification, carbon-credit eligibility, ROI, IRR, or customer case details.
- SEO keywords must match actual products and intent; GEO answers must be direct, bounded, and supported.
- An approved outline precedes body generation unless the user explicitly requests one-shot overall review. A final article package still needs human review before CMS work.
